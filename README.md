# webgame

웹 기반 일본식 리치마작(4인) 게임. 룰 엔진, 로컬(사람 1명 + 봇) 플레이, 서버 권위 온라인 대전(방 ID로 입장)까지 동작하는 개발 중인 프로젝트다.
진행 상황과 앞으로의 계획은 [`ROADMAP.md`](ROADMAP.md)를 본다.

## 패키지

- `packages/core` — 룰 엔진 (순수 로직)
- `packages/web` — 브라우저 클라이언트 (React + Vite). 로컬 모드와 온라인 모드
- `packages/server` — 서버 권위 WebSocket 게임 서버. 프로토콜, 환경변수, 한계는 [`packages/server/README.md`](packages/server/README.md) 참고

## 실행 방법

Node.js 22에서 개발·검증했다. 저장소 루트에서:

```bash
npm install          # 의존성 설치 (워크스페이스 전체)
npm run dev:all      # 서버(8080)와 웹(vite, 기본 http://localhost:5173)을 한 번에 실행. Ctrl+C로 둘 다 종료
npm run build        # core/server/web 빌드(타입 검사 포함)
npm test             # core + server + web 테스트
```

`npm run dev:all`은 `scripts/dev-all.mjs`가 서버와 vite를 각각 하나의 node 프로세스로 띄우고 출력에 `[server]`/`[web]` 접두어를 붙인다.
한쪽이 종료되면 나머지도 함께 종료한다. 셸을 거치지 않으므로 Windows(cmd/PowerShell)와 bash에서 똑같이 동작한다.
(터미널을 강제로 닫거나 `dev-all` 프로세스만 강제 종료하면 자식이 남을 수 있다. 그때는 8080/5173을 쓰는 프로세스를 직접 종료한다.)

따로 실행하고 싶으면:

```bash
npm run dev -w @mahjong/server   # 서버만 (기본 포트 8080)
npm run dev -w @mahjong/web      # 웹만 (http://localhost:5173)
```

### 로컬 모드와 온라인 모드

웹을 열면 모드 선택 화면이 나온다.

- **혼자 연습(로컬)**: 서버 없이 브라우저만으로 사람 1명 + 봇 3명. 서버가 필요 없다(`npm run dev -w @mahjong/web`만으로 충분).
- **온라인 대전**: 서버에 연결한다. `http://localhost:5173/?online=1`로 열면 모드 선택을 건너뛰고 바로 온라인 입장 화면으로 간다.

### 온라인 플레이 방법

1. `npm run dev:all`로 서버와 웹을 띄운다.
2. 브라우저에서 웹을 열고 "온라인 대전"을 고른다. 이름(1~32자)을 넣고 서버 주소(기본 `ws://localhost:8080`)를 확인한 뒤 "방 만들기"를 누르면 대기실이 나오고 **방 ID**가 표시된다.
3. 같이 할 사람에게 방 ID를 알려 준다. 두 번째 사람은 다른 브라우저 창 또는 **시크릿(InPrivate) 창**에서 웹을 열고(같은 브라우저의 일반 창은 저장된 세션(localStorage)을 공유한다) 온라인 대전 -> 방 ID 입력 -> "입장"을 누른다.
4. 대기실에서 누구든 "시작"을 누르면 게임이 시작되고 빈 좌석은 봇이 채운다(최대 사람 4명). **시작 후에는 새로 입장할 수 없다.**
5. 국이 끝나면 결과 창이 뜨고 약 5초 뒤 다음 국이 자동으로 시작된다("결과 닫기"로 먼저 닫을 수 있다). 게임이 끝나면 순위가 나오며 "나가기"로 입장 화면에 돌아간다. 온라인에는 새 게임 버튼이 없다(새 방을 만든다).
6. 내 차례 30초, 응답 15초 안에 행동하지 않으면 서버가 자동으로 처리한다(화면에 카운트다운 표시). 연결이 끊기면 자동으로 재접속을 시도하고, 새로고침해도 저장된 세션으로 이어서 접속한다.

원격 PC의 사람과 하려면 서버를 외부에서 접근 가능하게 만들고 서버 주소를 그 주소로 바꿔야 한다. TLS·IP 제한 등 운영 보호는 아직 없다(아래 "알려진 한계").

### 서버 환경변수와 포트 충돌

| 변수 | 대상 | 기본값 | 설명 |
|---|---|---|---|
| `PORT` | 서버 | `8080` | 서버 리슨 포트(`dev:all`은 빈 값·공백이면 8080으로 본다). `dev:all`은 이 값을 서버에 전달하고 웹의 기본 서버 주소도 `ws://localhost:$PORT`로 맞춘다 |
| `VITE_SERVER_URL` | 웹 | `ws://localhost:8080` (`dev:all`에서는 `ws://localhost:$PORT`) | 입장 화면에 미리 채워지는 서버 주소. 입장 화면에서 직접 바꿔도 된다 |

8080을 이미 쓰고 있으면 `dev:all`이 시작하기 전에 알려 주고 종료한다. 다른 포트로 실행하려면:

```bash
PORT=9090 npm run dev:all                      # bash
```

```powershell
$env:PORT=9090; npm run dev:all                # PowerShell (끝나면 Remove-Item Env:PORT)
```

```bat
set PORT=9090 && npm run dev:all               rem cmd
```

서버와 웹을 따로 띄운다면 서버는 `PORT=9090 npm run dev -w @mahjong/server`, 웹은 `VITE_SERVER_URL=ws://localhost:9090 npm run dev -w @mahjong/web`(PowerShell은 `$env:VITE_SERVER_URL=...`)으로 맞춘다.
웹 포트(5173)가 사용 중이면 vite가 자동으로 다음 포트(5174 등)를 쓴다(출력의 Local 주소를 확인). 그 밖의 서버 옵션(타임아웃, 한도)은 환경변수가 아니라 코드 옵션이다(서버 README).

## E2E (브라우저 자동 검증)

사람 2명(브라우저 컨텍스트 2개) + 봇 2명이 온라인 모드로 한 판을 끝까지 진행하는 자동화 스크립트다. `puppeteer-core`와 **시스템에 설치된 Edge(또는 Chrome)**를 쓰며 기본 `npm test`에는 포함되지 않는다.

```bash
npm run e2e -w @mahjong/web                     # 1회 (약 1분)
npm run e2e -w @mahjong/web -- --repeat 5       # 5회 반복(매 회 서버·vite·브라우저를 새로 띄우고 정리)
npm run e2e -w @mahjong/web -- --shots          # 주요 단계 스크린샷도 저장
```

- 서버·vite는 임의의 빈 포트로 띄우므로 개발 서버(8080/5173)와 충돌하지 않는다. 서버는 `packages/web/e2e/test-server.mts`(시작 점수 9000, 마감·응답 구간·봇 지연을 줄인 설정)를 쓴다.
- 브라우저 경로는 Windows/macOS/Linux의 흔한 Edge·Chrome 위치에서 찾는다. `E2E_BROWSER=<실행 파일 경로>`를 지정하면 그 경로만 쓰며, 경로가 없으면 다른 브라우저로 대체하지 않고 메시지와 함께 종료 코드 1로 실패한다. 환경변수가 없을 때만 자동 탐색하고, 탐색에 실패하거나 `puppeteer-core`가 없으면 이유를 출력하고 종료 코드 0으로 건너뛴다(CI에서는 조용한 통과가 될 수 있으니 `E2E_BROWSER`를 명시하는 편이 안전하다).
- 시나리오: 모드 선택 -> 온라인 -> 이름 -> 방 만들기 -> 두 번째 사람이 방 ID로 입장 -> 시작 -> UI 버튼/패 클릭으로 진행(B가 중간에 소켓을 강제로 닫고 자동 재접속) -> 결과 모달의 카운트다운과 자동 닫힘 -> (모달이 떠 있는 동안 연결 배너가 떠도 제목·버튼이 가려지지 않는지 390x844, 390x500, 768x500에서 `elementFromPoint`로 확인. 결과 모달이 짧으면 390x844만으로는 `--overlay-top` 유무를 가리지 못하므로 낮은 뷰포트 390x500·768x500이 그 역할을 한다. 긴 모달에서는 `--overlay-top`이 없으면 제목이 가려지고 있으면 가려지지 않음을 수동으로 확인했다) -> 게임 종료 순위 화면 -> 나가기 -> 콘솔 에러 0.
- 실패하면 어느 단계인지 출력하고 `packages/web/e2e/artifacts/`(git 제외)에 스크린샷을 남긴다. 첫 회 시작 때 이전 실행의 스크린샷(.png)을 지우고, 종료 시 서버·vite·브라우저를 정리하고 포트 해제를 확인한다.
- 1국에서 게임이 끝나 버리면(첫 판에 큰 화료) 결과 모달 자동 진행을 볼 수 없으므로 같은 회 안에서 최대 3번까지 새 방으로 다시 시도한다(출력에 재시도 사유가 나온다).

## 알려진 한계

- 룰: 패오(책임지불)와 인화는 미구현이고, 리치 후 깡은 금지다(대기가 변하지 않는 안깡 허용 룰 없음). 봇은 부로·깡·방어를 하지 않는다. 자세한 목록은 [`ROADMAP.md`](ROADMAP.md)의 "알려진 한계" 절.
- 서버: 영속화 없음(재시작하면 방 소멸), 배포 구성(TLS, 프로세스 관리, IP/연결 수 제한) 없음, 로그인 없음(좌석 토큰이 곧 권한). [`packages/server/README.md`](packages/server/README.md)의 "알려진 한계와 보안 메모".
- 웹(온라인): 시작 전 대기실에서 누가 앉았는지 알 수 없고 시작 권한자 구분이 없다(서버가 알려 주지 않음), 새로고침 직후에는 카운트다운이 실제보다 최대 약 5초 길게 보일 수 있다, 서버 모드에는 행동 로그가 없다. 전체 목록은 ROADMAP의 "3단계 남은 항목".
