# 17-1 나머지 일반 역과 쿠이사가리 (code-writer)

유국만관과 쿠이가에시는 17-2 범위라 하지 않았다. `역.txt`/`server/`는 읽기만 했고 커밋/ROADMAP 수정은 하지 않았다.

## 설계
- 판수 구조: `YAKU_HAN: Record<YakuId, { menzen, open }>`. 후로 불가는 `open: 0`, 역만은 `{0,0}`. 접근자 `yakuHan(id, concealed)`. 멘젠 여부는 `isContextConcealed(ctx)`(안깡은 멘젠 유지).
- `ScoreResult.yaku[].han`은 실제 적용 판수(후로면 후로 판수). web은 이미 `ScoreResult`의 `y.han`을 쓰고 `YAKU_HAN`을 직접 보지 않아 수정 없음.
- 새 역 판정(`yaku.ts`):
  - 분해 단위(`shapeYakuForDecomposition`, 부로 멜드 포함): 삼색동각, 산깡쯔(깡 정확히 3개), 소삼원, 일기통관, 삼색동순, 찬타/준찬타, 량페코/이페코, 혼노두(표준형).
  - 패 구성 단위(`detectContextYaku`, 손패+멜드 전체): 혼일색, 청일색. 치또이쯔 형태에도 자동 적용.
  - 혼노두는 국사무쌍 형태에 붙으면 안 되므로 표준형 분해/치또이쯔 형태에서만 판정(`isHonroutou`).
  - 이페코 판정을 "동일 순자 쌍 개수"로 바꿈: 1쌍이면 이페코, 2쌍 이상(4벌 포함)이면 량페코(배타). 멘젠 한정.
- 후보 처리: `score.ts` 후보 비교(기본점, 판수, 부수)는 그대로. 후보별 판수 합산에 `yakuHan(id, concealed)` 사용. `detectYaku`는 기존대로 분해별 합집합이며, 량페코가 있으면 이페코를 제거한다. (알려진 한계: 합집합이라 치또이쯔와 량페코가 같은 손패에서 함께 표시될 수 있다. 점수는 `calculateScore`가 최고 후보 하나만 채택하므로 정확하다.)

## 정정한 기존 테스트
- `score.test.ts` "치또이쯔와 표준형이 모두 가능하면 더 높은 쪽을 채택" (`11m 22m 33m 44m 55m 66m 77m`, 1m 론, 리치): 한 슈트라 청일색 6판이 붙고 표준형은 량페코가 된다. 치또이쯔 후보 = 리치1+치또이쯔2+청일색6 = 9판 배만(4000). 표준형 후보 = 리치1+핑후1+량페코3+청일색6 = 11판 삼배만(6000, 론 24000). 표준형 채택으로 기대값을 정정(역 `chinitsu,pinfu,riichi,ryanpeikou`, 11판, 삼배만).
- `situational.test.ts`, `yakuman.test.ts`의 `YAKU_HAN[id]` 숫자 단언은 `{menzen, open}` 구조에 맞게 변경(값은 동일).
- `yakuman.test.ts` "국사무쌍은 멘젠이 아니면 성립하지 않는다": 변경 없이 통과하도록 혼노두를 국사무쌍 형태에서 제외(단언에 사유 주석만 추가).
- `yakuman.test.ts` "구련보등 멘젠이 아니면 성립하지 않는다": 비멘젠 구련보등 형태는 이제 청일색이 성립하므로 `[]` 단언을 "구련보등 역만 없음 + 청일색 있음"으로 정정.

## 추가 테스트
