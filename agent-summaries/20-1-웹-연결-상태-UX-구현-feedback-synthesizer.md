# 20-1 웹 연결 상태 UX 구현 종합 (feedback-synthesizer)

> feedback-synthesizer에는 Write 도구가 없어 메인 세션이 보고 내용을 저장했다.
> 종합 에이전트는 StatusStack.tsx, messages.ts, useServerGame.ts, styles.css를 읽었고, App.tsx, entry.ts, 요약 문서 2개는 읽지 않았다. 7번 재현 경로는 검증 리포트 서술을 근거로 했다.

## 요약
검증 발견 7건과 작성자 한계, 통합 테스트 불안정을 분류했다. 이 단계에서 고칠 것은 1, 2, 3, 7, 5(문구), 6(방어 한 줄), acts>=10 단언. 다음 단계로 넘길 것은 4번과 정적 '약 N초' 문구, 1008 구분. 고치지 않아도 되는 것은 오류 알림 인라인 레이아웃 이동.

## 이 단계에서 고칠 것
| 순위 | 항목 | 근거 |
|---|---|---|
| 1 | 1번: 배너가 헤더 '나가기'를 가림 | 재접속 중 탈출 수단이 막힘 |
| 2 | 2번: 서버 주소 전환 안내가 바로 사라짐 | 사용자가 못 보면 기능이 없는 것과 같음 |
| 3 | 3번: 재접속 화면 인라인 문구 중복, closed의 인라인 '나가기' 안내와 배너 '다시 연결' 상충 | 1번과 같은 배치를 건드리므로 함께 |
| 4 | 7번: 다른 서버 세션이 저장된 채 연결 실패 시 '다시 연결' 버튼이 뜸 | 누르면 오류가 나는 버튼, 변이 생존으로 테스트 공백 확인 |
| 5 | 통합 테스트 acts>=10 불안정 | 재현율 약 10% |
| 6 | 5번: 방이 사라진 경우 문구 | 문구 한 줄 |

## 수정 지시
- 1번: StatusStack에 `onLeave?: () => void` prop 추가. connection.kind가 reconnecting이거나 closed일 때 '나가기' 버튼(비강조)을 배너 안에 렌더링, App에서 c.leave 전달. 390px에서 헤더를 덮지 않게 상단 고정 + 헤더 아래 오프셋(`--header-h`), 하단 고정은 패 조작을 가릴 위험이 있어 비권장. 테스트: reconnecting 배너 안 나가기 버튼과 호출, closed에서 나가기와 다시 연결 둘 다 표시. 변이: 나가기 렌더 조건 삭제. 브라우저: 390/768px에서 elementFromPoint로 헤더 버튼이 눌리는지.
- 2번: switchNote를 입장 순간 지우지 않고 방에 들어간 뒤에도 닫기 또는 나가기 전까지 유지하는 닫기 가능한 카드로. 테스트: 서버 주소를 바꿔 입장한 뒤에도 남아 있음, 닫기 시 사라짐. 변이: 입장 시점 삭제 복원.
- 3번: status가 reconnecting/closed이고 방에 있으면 인라인 안내를 렌더링하지 않고 배너만. closed 인라인 '나가기 안내' 삭제. 테스트: 인라인 testid 없음. 변이: 인라인 조건 복원.
- 7번: resumable 계산을 한 함수 `isResumable(store, url)`로 모아 훅·wsClient·entry.ts의 모든 경로에서 serverUrl 비교. 테스트: 다른 URL 세션 + closed면 '다시 연결' 없음, 같은 URL이면 있음. 변이: URL 비교 제거. (실제 경로는 코드를 따라가며 확정할 것)
- 5번: 서버 재기동으로 방이 사라진 경우(자동 rejoin 경로의 unknown_room)에는 "방이 사라졌습니다. 서버가 다시 시작되었거나 방이 닫혔을 수 있습니다."로, 사용자가 방 ID를 직접 입력한 경우 문구는 유지. 테스트: 두 경로 문구가 다름.
- 6번: 서버 오류 이벤트 처리에서 ack 타이머를 지울 때 acked도 false로(ackedRef, patch). 단위 테스트 하나.
- 통합 테스트: `acts>=10`을 `acts>=1 && (acts>=10 || gameEnded)`로 완화(시드 고정이 가능하면 고정). 행동 0회면 실패하는지 변이 확인, 30회 반복 확인.

## 패턴·재발 위험
- 배치 문제는 단위 테스트로 못 잡음: 오버레이를 추가할 때 좁은 폭(390px)과 elementFromPoint 확인을 체크리스트에 넣을 것. 마감·결과 UI가 같은 fixed 패턴을 쓰면 반복될 수 있음.
- 안내의 수명 관리: 일회성 안내가 다른 상태 전이에 조용히 지워지는 문제. 안내마다 '무엇이 지우는가' 표를 둘 것.
- 같은 사실의 중복 계산: resumable이 훅·wsClient·entry.ts에 각각 있음. 한 함수로.
- 변이 생존 반복: 각 수정마다 변이를 실제로 실행.
- 통합 테스트가 무작위 판 길이에 의존하는 한 같은 불안정이 재발.
