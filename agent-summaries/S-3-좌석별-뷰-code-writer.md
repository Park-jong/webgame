## 설계 판단
- 안깡: 실제 마작에서 선언 시 패를 보여 주므로 종류와 적5 여부까지 상대에게 공개 (core `AnkanMeld.tiles` 그대로).
- 뽑은 패: 본인 차례(`phase === "turn"`)에만 `drawnTile`. 상대는 `handCount`(뽑은 패 포함 장수)로 14장 여부만 알 수 있다.
- 국 종료: 결과(type/deltas/dealerContinues/reason), 화료자 손패·멜드·화료패·점수 내역은 공개. 뒷도라 표시패는 리치한 화료자가 있을 때만 공개. 황패평국은 core가 담는 `tenpai` 배열만 공개하고 텐파이자 손패는 공개하지 않음(보수적). 진행 중에는 `result: null`.
- 응답 대기: `awaitingSeats`와 `pending.awaiting`을 뷰에서 제거하고 본인에게만 `awaitingYou: boolean`을 준다(상대의 부로/론 가능 여부 누출 차단). 남은 위험: 응답 대기 종료 타이밍으로 추측 가능하므로 S-5 서버 루프는 응답 가능 여부와 무관하게 동일한 지연으로 진행해야 한다. 서버 루프는 뷰가 아니라 state의 awaitingSeats를 직접 쓴다.
- 낮은 심각도 한계(주석 명시): 안깡 적5 공개, 14장 상태 후리텐 표시는 임시 플래그만 반영.
- 후리텐: core `isFuriten` 그대로. 14장(뽑은 직후) 상태에서는 임시 후리텐 플래그만 반영된다.
- 봇이 거의 리치로만 화료해 비리치 화료는 시뮬레이션에서 나오지 않아, 뒷도라 비공개 케이스는 리치 플래그를 끈 사본으로 검증. 깡이 시뮬레이션에서 나오는지는 단언하지 않음(안깡 공개는 수동 구성 상태로 검증).
